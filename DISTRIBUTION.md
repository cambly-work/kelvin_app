# Kelvin — как безопасно раздавать приложение

Короткий практичный гайд: как отдать Kelvin людям так, чтобы у них он открывался без страшных
предупреждений, и чтобы никто не подсунул заражённую копию под твоим именем.

---

## 1. Честная правда про «чтобы не украли»

Kelvin теперь **бесплатный**. Значит «кража лицензии» больше не проблема — воровать нечего.
Реальные угрозы у бесплатной утилиты другие:

- **(а) Подмена бинарника.** Кто-то скачает Kelvin, зашьёт внутрь вирус и раздаёт «твой» заражённый DMG.
- **(б) Пугающие окна у пользователей.** Без подписи macOS покажет «Kelvin повреждён» или «неустановленный
  разработчик» — люди испугаются и удалят.
- **(в) Выдача чужими за своё.** Кто-то переклеит иконку/имя и назовёт своим.

Защита от всего этого — **не DRM, а подпись + нотаризация + проверка целостности**. Это как печать и
голограмма на упаковке: подделать бинарник можно, но он перестанет быть «подписанным тобой», и это видно.

> Абсолютной защиты от реверс-инжиниринга нативного бинарника не существует, и для бесплатного
> инструмента это нормально — гнаться за ней не нужно. Цель — чтобы **твоя официальная сборка**
> была узнаваемой и открывалась чисто.

---

## 2. Минимум для безопасной раздачи (обязательно)

Три вещи. Без них публично раздавать нельзя.

1. **Apple Developer ID.** Нужен аккаунт Apple Developer Program ($99/год; для организации через CNPJ —
   сперва бесплатный номер D-U-N-S). Из него выпускается сертификат **Developer ID Application** — им ты
   «расписываешься» в бинарнике.
2. **Подпись (`codesign`) с hardened runtime.** Ставит твою печать и включает защищённый режим запуска.
   После этого любая правка файла ломает подпись — заражённая копия становится «не твоей».
3. **Нотаризация (`notarytool`) + staple.** Ты отправляешь DMG в Apple, её робот проверяет его на малварь и
   выдаёт «квитанцию». `staple` вклеивает эту квитанцию внутрь DMG. Итог: **пользователь открывает Kelvin
   двойным кликом без единого предупреждения**, даже офлайн.

Простыми словами: **подпись = это точно я; нотаризация = Apple проверила, что тут нет вируса.**

---

## 3. Как это сделать здесь (уже всё готово в `release.sh`)

Весь пайплайн собран в одном скрипте. Он делает: **сборка → тесты → подпись Developer ID + hardened
runtime → DMG → нотаризация → staple → генерация appcast**.

### Шаг 1. Один раз: настроить учётку Apple для нотаризации

Нужен app-specific пароль (создаётся на https://appleid.apple.com → «Пароли приложений»).

```sh
xcrun notarytool store-credentials "kelvin-notary" \
    --apple-id cambly.studio@gmail.com \
    --team-id <ТВОЙ_TEAM_ID> \
    --password <app-specific-пароль>
```

`kelvin-notary` — это имя профиля, его дальше передаём как `AC_PROFILE`.

### Шаг 2. Узнать имя сертификата (`DEVID_APP`)

После установки сертификата в Keychain посмотри точное имя:

```sh
security find-identity -v -p codesigning
```

Строка вида `Developer ID Application: Artem Balabanov (ABCDE12345)` — целиком это и есть `DEVID_APP`.
В скобках — твой **Team ID** (пригодится в п.5).

### Шаг 3. Собрать релиз одной командой

```sh
DEVID_APP="Developer ID Application: Artem Balabanov (ABCDE12345)" \
AC_PROFILE="kelvin-notary" \
DOWNLOAD_BASE="https://trykelvin.com" \
STYLE_DMG=1 \
./release.sh
```

- `DEVID_APP` — сертификат подписи (из шага 2).
- `AC_PROFILE` — профиль нотаризации (из шага 1).
- `DOWNLOAD_BASE` — адрес, где будет лежать DMG (для автообновлятора).
- `STYLE_DMG=1` — красиво разложить окно DMG через Finder (для финального релиза).

На выходе — `Kelvin-0.9.0.dmg`: подписан, нотаризован, заштаплен. Готов к раздаче.

### Шаг 4. Проверить, что всё легально

```sh
# развернуть DMG (двойной клик), затем по Kelvin.app внутри:
codesign -dv --verbose=4 /Volumes/Kelvin/Kelvin.app   # видно Authority: Developer ID + твой Team ID
spctl -a -vvv /Volumes/Kelvin/Kelvin.app              # ждём: accepted, source=Notarized Developer ID
xcrun stapler validate Kelvin-0.9.0.dmg               # ждём: The validate action worked
```

Если все три зелёные — у пользователя откроется без предупреждений.

## 4. Если Developer ID пока НЕТ (ad-hoc) — только для себя

Без `DEVID_APP` скрипт всё равно соберёт DMG, но **ad-hoc**: без подписи и нотаризации.
Что увидит человек:

- «**Kelvin повреждён и не может быть открыт. Переместите в Корзину**», либо блок «неустановленный разработчик».

Обходится вручную:

```sh
# правый клик по приложению → «Открыть» → «Открыть» (разово)
# или снять карантин целиком:
xattr -dr com.apple.quarantine /Applications/Kelvin.app
```

**Но это НЕ для публичной раздачи.** Просить незнакомых людей «снять карантин командой в терминале» —
ровно то, что делают вирусы. Это отпугнёт и подорвёт доверие.

> **Вывод: получи Developer ID до публичного релиза.** Ad-hoc — только чтобы гонять сборку у себя.

## 5. Целостность и bundle id (сделать перед релизом)

**Bundle id.** Уже в порядке: в `Info.plist` стоит доменный `com.trykelvin.kelvin` (не временный
`com.local.*`). Просто убедись, что не откатился — `release.sh` сам падает, если id начинается с `com.local.`.

**Впиши свой Team ID для самозащиты.** Открой `Sources/Hardening.swift` и замени:

```swift
static let expectedTeamID: String? = nil
```

на свой Team ID (те же символы из скобок в `DEVID_APP`):

```swift
static let expectedTeamID: String? = "ABCDE12345"
```

Что это даёт: приложение при запуске проверяет **собственную подпись**. Если кто-то пропатчит бинарник и
переподпишет своей ad-hoc-подписью, проверка не пройдёт — это дополнительный сигнал, что копия не твоя.
Работает мягко (не роняет приложение у честного пользователя). Сейчас, пока там `nil`, самопроверка выключена.

## 6. Чек-лист перед публикацией

- [ ] Версия поднята в `Info.plist` (`CFBundleShortVersionString` **и** `CFBundleVersion`)
- [ ] Иконка на месте (`Resources/AppIcon.icns`)
- [ ] `expectedTeamID` в `Hardening.swift` = твой реальный Team ID
- [ ] `./release.sh` прошёл **с** `DEVID_APP` и `AC_PROFILE` (не ad-hoc)
- [ ] `codesign -dv` показывает Developer ID и Team ID
- [ ] `spctl -a -vvv` → `accepted / Notarized Developer ID`
- [ ] `xcrun stapler validate` → OK
- [ ] Проверено на **чистой машине или под другим аккаунтом** (двойной клик открывает без предупреждений)
- [ ] Ссылки на сайте/лендинге ведут на актуальный DMG и работают

---

## 7. Где и как раздавать

- **Хостинг:** свой сайт или **GitHub Releases** — прямая ссылка на нотаризованный `Kelvin-X.Y.dmg`.
  Проще всего GitHub Pages из папки `docs/` (там уже лежат лендинг и `appcast.json` для автообновлений).
- Раздавай **только нотаризованный DMG**. Никаких «снимите карантин» в инструкции.
- **SHA-256 чек-сумма.** Опубликуй рядом с ссылкой — чтобы пользователь мог проверить, что скачал именно
  твой файл, а не подменённый:

  ```sh
  shasum -a 256 Kelvin-0.9.0.dmg
  ```

  Публикуешь эту строку на странице загрузки. Пользователь сверяет ту же команду у себя — совпало
  = файл целый и настоящий.

---

### TL;DR

1. Получить **Apple Developer ID** ($99/год).
2. `xcrun notarytool store-credentials` — один раз.
3. `DEVID_APP=… AC_PROFILE=… ./release.sh` — собирает подписанный + нотаризованный DMG.
4. Вписать Team ID в `Hardening.swift`.
5. Проверить `spctl`/`stapler`, посчитать SHA-256, выложить.
