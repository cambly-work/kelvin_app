# План для ИИ: безопасная очистка старой версии Kelvin перед установкой из DMG

## Контекст

Репозиторий собирает macOS-приложение `Kelvin.app` и образ `Kelvin-<version>.dmg`.
Раньше приложение называлось `BatteryMeter`, поэтому на машине могут одновременно
остаться старые bundle/launchd-объекты с именами Kelvin и BatteryMeter.

В проекте уже есть частичная очистка:

- `uninstall-app.sh` — останавливает приложение и удаляет app bundle/старый LaunchAgent;
- `helper/uninstall-helper.sh` — удаляет root-демон телеметрии powerd;
- `helper/uninstall-fan-helper.sh` — удаляет root-демон вентиляторов;
- `install-app.sh` — заменяет приложение в `/Applications` и удаляет часть legacy-объектов;
- `make-dmg.sh` — собирает DMG.

Нужно не дублировать эту логику вслепую, а привести её к одному безопасному сценарию.

## Задача

Реализуй скрипт `clean-old-version.sh`, который безопасно удаляет старую установленную
версию Kelvin/BatteryMeter и оставшиеся службы перед чистой установкой новой версии.
При необходимости минимально обнови существующие uninstall/install/build-документы,
чтобы новый сценарий был понятен и не расходился с ними.

Скрипт предназначен для запуска пользователем на macOS из распакованного репозитория
или рядом с новой сборкой. Он не должен удалять исходники, локальный `Kelvin.app` в
репозитории, создаваемый DMG или любые посторонние файлы.

## Обязательное поведение

1. Используй Bash и строгий режим (`set -euo pipefail`), но ожидаемые ситуации
   «процесс/файл/служба уже отсутствует» обрабатывай идемпотентно.
2. По умолчанию выполняй безопасную очистку с сохранением пользовательских данных:
   - остановить процессы `Kelvin` и `BatteryMeter`;
   - снять старые пользовательские LaunchAgents:
     - `~/Library/LaunchAgents/com.local.batterymeter.plist`;
     - `~/Library/LaunchAgents/com.trykelvin.kelvin.login.plist`;
   - удалить только установленные bundles:
     - `/Applications/Kelvin.app`;
     - `/Applications/BatteryMeter.app`;
   - корректно остановить и удалить legacy/current root launchd-службы:
     - `com.trykelvin.kelvin.powerd`;
     - `com.trykelvin.kelvin.fand`;
     - `com.local.batterymeter.powerd`;
     - `com.local.batterymeter.fand`;
   - удалить только принадлежащие этим службам plist и payload-файлы из
     `/Library/LaunchDaemons` и `/Library/Application Support/Kelvin`;
   - удалить `/Library/Application Support/BatteryMeter`, так как это legacy-каталог;
   - попытаться удалить `/Library/Application Support/Kelvin` через `rmdir`, только
     если после точечной очистки он пуст.
3. Учти современный privileged daemon `com.trykelvin.kelvin.privileged`, который
   регистрируется через `SMAppService` и находится внутри app bundle. Сначала изучи
   `Sources/PrivilegedServiceManager.swift` и выбери корректный способ unregister/
   bootout для поддерживаемых macOS. Не оставляй активную службу, ссылающуюся на уже
   удалённый bundle. Не удаляй произвольные записи ServiceManagement.
4. Не удаляй в обычном режиме:
   - `~/Library/Preferences/com.trykelvin.kelvin.plist` и UserDefaults;
   - `~/Library/Application Support/Kelvin` (профили, CrashReports и другие данные);
   - Keychain-записи лицензии/trial;
   - настройки Accessibility, Notifications и другие TCC-разрешения;
   - fan profile пользователя;
   - любые файлы по маске/широкому glob, если точный владелец не доказан.
5. Добавь отдельный явный флаг `--purge-user-data` для полного пользовательского
   удаления. Перед ним покажи точный список целей и потребуй интерактивное
   подтверждение, кроме случая с дополнительным флагом `--yes`. Даже purge не должен
   пытаться сбрасывать TCC целиком или затрагивать данные других приложений.
6. Добавь `--dry-run`: он печатает все действия и ничего не меняет, не вызывает sudo,
   не останавливает процессы и не запускает `launchctl` с изменяющими командами.
7. Не запускай весь скрипт через sudo. Сначала выполни пользовательскую часть от
   текущего пользователя, затем запроси повышение прав ровно для системной части.
   Если root-объектов нет, sudo вообще не нужен. Не вычисляй домашний каталог из
   `$HOME` после повышения прав.
8. Защити все destructive targets allowlist-проверкой: удаляются только перечисленные
   абсолютные пути. Запрещены неразрешённые переменные, широкие globs и рекурсивное
   удаление пустого/корневого пути.
9. Скрипт должен быть повторно запускаемым и завершаться успешно, если старая версия
   уже полностью отсутствует. В конце выдай краткий отчёт: что удалено, что не найдено,
   что сохранено и были ли ошибки.
10. Если какой-либо обязательный этап не удался, верни ненулевой exit code и не
    сообщай «очистка завершена успешно».

## Интеграция со сборкой/DMG

- Не запускай очистку автоматически из `build.sh` или `make-dmg.sh`: сборка артефакта
  не должна менять установленную систему разработчика.
- Добавь `clean-old-version.sh` в корень репозитория и при необходимости копируй его
  в DMG под понятным именем вроде `Remove old Kelvin.command`, только если это не
  ухудшает UX drag-to-Applications. Если добавляешь `.command`, обеспечь executable bit
  и не ломай Finder-раскладку/фон.
- Предпочтительный простой UX: документировать ручной запуск скрипта для проблемной
  чистой переустановки, а обычное обновление оставить заменой app bundle.
- Не включай очистку пользовательских данных в обычную установку или обновление.

## Согласование существующих скриптов

После реализации проверь `uninstall-app.sh`, `helper/uninstall-helper.sh`,
`helper/uninstall-fan-helper.sh` и `install-app.sh`. Устрани противоречия одним из
вариантов:

- существующие скрипты вызывают общий новый helper/режим; или
- новый скрипт переиспользует их, если можно гарантировать строгий режим, dry-run,
  корректный exit code и одинаковую allowlist-семантику.

Не оставляй несколько расходящихся списков путей без объяснения. Не делай большой
рефакторинг Swift-кода, если он не требуется для корректного unregister службы.

## Проверка

Выполни и зафиксируй результаты:

1. `bash -n clean-old-version.sh` и синтаксическую проверку всех изменённых shell-файлов.
2. Запуск `./clean-old-version.sh --dry-run` без sudo: убедись, что система не меняется.
3. Повторный dry-run на состоянии «ничего не установлено».
4. Статическая проверка, что destructive-команды получают только allowlisted paths.
5. Проверка, что обычный режим не удаляет preferences, Keychain и пользовательский
   `~/Library/Application Support/Kelvin`.
6. Если доступен безопасный тестовый стенд: создать фиктивное дерево в переназначаемом
   test root и проверить cleanup дважды. Для тестируемости разрешено добавить
   недокументированную переменную root только для тестов, но production-запуск обязан
   отвергать опасные/пустые значения.
7. Запусти существующие релевантные тесты проекта, если изменения затронули Swift или
   сборщик. Не подписывай, не нотаризуй и не публикуй релиз без отдельного разрешения.

## Ограничения работы в текущем репозитории

Рабочее дерево уже содержит незакоммиченные пользовательские изменения, в том числе
в `make-dmg.sh`, ресурсах DMG и Swift-файлах. Не откатывай, не форматируй массово и не
перезаписывай их. Перед редактированием выполни `git status --short` и изучи diff
каждого файла, который собираешься менять. Сохрани все посторонние изменения.

Не создавай commit и не выполняй push без отдельной просьбы пользователя.

## Формат отчёта исполнителя

В конце сообщи:

- какие файлы изменены;
- точную семантику обычного режима, `--dry-run`, `--purge-user-data` и `--yes`;
- как обрабатывается privileged/SMAppService daemon;
- какие проверки реально выполнены и их результат;
- какие проверки не удалось выполнить на текущей машине;
- оставшиеся риски или ручные шаги.
