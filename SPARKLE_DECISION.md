## Продуктовые решения

### 1. Каналы обновлений

**Решение**: Только `stable` на первом этапе.

- `beta` канал отложить до появления публичной beta-программы
- Один appcast: `https://trykelvin.com/appcast.xml`
- При необходимости beta будет отдельный feed: `appcast-beta.json`

### 2. Автоустановка

**Решение**: Автозагрузка включена, автовстановка — запрос пользователя.

- `SUAutomaticallyUpdateAtLaunch = NO` — не устанавливать без спроса
- `SUAutomaticallyCheckForUpdates = YES` — проверять в фоне
- `SUEnableAutomaticDownloads = YES` — загружать заранее
- Пользователь видит: «Доступна версия X.X.X» → кнопки:
  - «Установить и перезапустить»
  - «Позже»
  - «Что нового»

### 3. Политика пропуска версии

**Решение**: Сохранить существующее поведение.

- Мигрировать `updates.skip` из старых настроек
- Кнопка «Пропустить эту версию» только при фоновой проверке
- При ручной проверке — только «Позже»
- Сброс пропуска при следующем мажорном обновлении

### 4. Staged Rollout

**Решение**: Отложить.

- Не требуется на текущем масштабе
- Добавить при росте аудитории >10,000 пользователей
- При необходимости: использовать `phasedRolloutInterval` в appcast

### 5. Срок хранения артефактов

**Решение**: Минимум 3 последние версии + текущая.

- Хранить DMG для: текущей + 3 предыдущих версий
- Минимум 90 дней доступности для каждой версии
- Критические security updates — бессрочно до следующего патча

### 6. Минимальная версия macOS

**Решение**: Оставить macOS 11.0.

- Текущая: `LSMinimumSystemVersion = 11.0`
- Sparkle 2 поддерживает до 10.13, так что запас есть
- Пересмотреть при использовании API macOS 12+

### 7. Privileged Service (fand)

**Решение**: Реализовать handshake протокола.

- Добавить версию протокола в Info.plist service
- Проверка совместимости после обновления app
- Если несовместим — показать диалог обновления service
- Запрос авторизации только когда действительно нужно
- Откат service при неудаче

## Security-настройки

### Обязательные ключи Info.plist

```xml
<!-- Feed URL -->
<key>SUFeedURL</key>
<string>https://trykelvin.com/appcast.xml</string>

<!-- Public EdDSA key (будет сгенерирован) -->
<key>SUPublicEDKey</key>
<string>...</string>

<!-- Безопасность -->
<key>SURequireSignedFeed</key>
<true/>

<key>SUVerifyUpdateBeforeExtraction</key>
<true/>

<key>SUPromptUserOnFirstLaunch</key>
<false/>

<!-- Поведение -->
<key>SUAutomaticallyCheckForUpdates</key>
<true/>

<key>SUEnableAutomaticDownloads</key>
<true/>

<key>SUAutomaticallyUpdateAtLaunch</key>
<false/>

<key>SUEnableSystemProfiling</key>
<false/>

<key>SUSendProfileInfo</key>
<false/>
```

### Генерация ключей EdDSA

**Команда для генерации**:

```bash
./bin/generate_keys
```

**Где хранить**:

- ❌ Приватный ключ: НЕ в репозитории, НЕ в .app
- ✅ Приватный ключ: CI secret / keychain релизной машины
- ✅ Публичный ключ: встраивается в Info.plist

**Процедура ротации**:

1. Сгенерировать новую пару ключей
2. Добавить публичный ключ в appcast как `<sparkle:edSignature>`
3. Выпустить обновление приложения с новым `SUPublicEDKey`
4. После распространения — отозвать старый ключ
5. Документировать в runbook

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Sparkle не работает с не-Xcode сборкой | Низкая | Высокое | Тестировать на раннем этапе |
| Пользователи macOS 11 не получают обновления | Низкая | Среднее | Sparkle поддерживает 10.13+ |
| Потеря update signing key | Средняя | Критическое | Backup key в secure storage, runbook ротации |
| Обновление ломает fand service | Средняя | Высокое | Handshake протокол, откат |
| Gatekeeper блокирует установку | Низкая | Высокое | Правильная подпись + нотаризация |

- [ ] Обновление устанавливается из приложения без ручного DMG/copy
- [ ] Повреждённый или неподписанный артефакт не устанавливается
- [ ] Текущая рабочая версия сохраняется при ошибке
- [ ] Пользователь видит прогресс и понятный результат
- [ ] Update check не передаёт лишние данные
- [ ] Есть проверенный путь обновления app + fand service
- [ ] Работает на macOS 11.0+ и современном macOS
- [ ] Release runbook проверен реальным обновлением N → N+1
