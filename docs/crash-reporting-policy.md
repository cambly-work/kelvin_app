# Политика отправки отчётов о сбоях Kelvin

## Введение

Этот документ определяет политику сбора, обработки и отправки отчётов о сбоях приложения Kelvin. Политика разработана с приоритетом приватности пользователя и соответствует заявленным принципам локальности данных.

## Основные принципы

1. **Явное согласие по умолчанию**: отправка отчётов о сбоях требует явного действия пользователя
2. **Минимизация данных**: отправляются только данные, необходимые для диагностики
3. **Прозрачность**: пользователь видит содержимое отчёта до отправки
4. **Локальная обработка**: санитизация и подготовка происходят на устройстве
5. **Без повторной отправки**: каждый crash отправляется не более одного раза

## Что НЕ отправляется (строго запрещено)

Следующие данные никогда не включаются в отчёт о сбое:

- Полное содержимое системных `.ips` файлов без санитизации
- Имя пользователя macOS и домашний путь (`/Users/username`)
- Серийный номер устройства
- Hardware UUID
- Лицензионный ключ Kelvin
- Email адрес пользователя
- IP-адреса, собранные приложением
- Содержимое буфера обмена
- Набранные слова и текст автозамены
- Пути и имена пользовательских документов
- Список открытых окон и приложений
- Произвольные логи shell-команд
- SMC raw dump без отдельного показа и согласия
- Аргументы командной строки
- Environment переменные процесса

## Разрешённые данные (allowlist)

После санитизации отчёт может содержать следующие поля:

### Идентификаторы и версии
- `schema_version` — версия схемы отчёта
- `app_version` — версия Kelvin (CFBundleShortVersionString)
- `app_build` — номер сборки (CFBundleVersion)
- `macos_version` — версия macOS
- `macos_build` — сборка macOS
- `hw_model` — модель Mac (например, "MacBookPro18,3")
- `architecture` — архитектура процессора (arm64/x86_64)

### Информация о падении
- `exception_type` — тип исключения
- `exception_signal` — сигнал POSIX (если применимо)
- `termination_reason` — причина завершения
- `crashed_thread_name` — имя упавшего потока (если есть)
- `crashed_thread_frames` — стек вызовов упавшего потока (ограничено)

### Binary images (ограниченно)
- Только для бинарного файла Kelvin
- Только для системных Apple frameworks
- UUID бинарных файлов для symbolication

### Контекст приложения
- `kelvin_service_version` — версия Kelvin service (если установлен)
- `feature_states` — флаги функций без содержимого
- `breadcrumbs` — последние события из allowlist (макс. 50)

### Метаданные
- `timestamp` — время падения (с точностью до минуты)
- `report_id` — уникальный идентификатор отчёта (UUID)

## Breadcrumbs (допустимые события)

Разрешены только следующие типы событий для breadcrumbs:

```swift
enum CrashBreadcrumb {
    case appStarted
    case popoverOpened
    case popoverClosed
    case settingsOpened(section: String)
    case settingsClosed
    case helperConnectionChanged(state: String)
    case updateStateChanged(state: String)
    case sensorAvailabilityChanged(state: String)
    case licenseCheckPerformed(result: String)
    case backgroundTaskStarted(name: String)
    case backgroundTaskCompleted(name: String)
}
```

**Запрещено**: произвольные строки, пользовательский ввод, сетевые адреса, названия файлов.

## Хранение и lifecycle отчётов

### Локальное хранилище
Отчёты хранятся в:
```
~/Library/Application Support/Kelvin/CrashReports/
```

### Статусы отчёта
Каждый отчёт проходит через следующие состояния:
- `discovered` — обнаружен новый crash report
- `reviewed` — пользователь просмотрел отчёт
- `consented` — получено согласие на отправку
- `queued` — отчёт добавлен в очередь отправки
- `sent` — успешно отправлен
- `declined` — пользователь отказался от отправки
- `expired` — истёк срок хранения (7 дней)

### Сроки хранения
- Отправленные отчёты: удаляются через 24 часа после успешной отправки
- Отклонённые отчёты: хранятся 7 дней, затем удаляются
- Ожидающие отправки: хранятся 7 дней

## Согласие пользователя

### Режимы отправки

#### Ручная отправка (по умолчанию)
При обнаружении нового crash report:
1. При следующем запуске показывается карточка с уведомлением
2. Пользователь видит санитизированное содержимое
3. Доступные действия:
   - «Посмотреть» — открыть полный preview
   - «Отправить» — отправить один отчёт
   - «Не отправлять» — отклонить и не показывать повторно
   - «Скопировать» — скопировать JSON в буфер
   - «Сохранить в файл» — экспортировать как файл

#### Автоматическая отправка (opt-in)
Пользователь может включить настройку:
```
«Автоматически отправлять обезличенные отчёты о сбоях»
```

Даже при включённой автоматической отправке:
- Настройка выключена по умолчанию
- Пользователь может отключить в любой момент
- Доступна история последних отправок
- Можно открыть и просмотреть любой санитизированный payload

### UI требования
- Никаких dark patterns
- Не связывать отправку с лицензией или функциональностью
- Спокойный, информативный тон уведомлений
- Чёткое указание endpoint для отправки
- Ссылка на политику конфиденциальности

## Технические требования к отправке

### Endpoint
```
POST https://trykelvin.com/api/v1/crash-reports
Content-Type: application/json
```

### Требования к клиенту
- Отдельная `URLSession` с timeout 30 секунд
- Exponential backoff при ошибках сети
- Максимум 3 попытки повтора для 5xx ошибок
- Не повторять 4xx ошибки (кроме 429)
- Не блокировать запуск или выход приложения
- Поддержка отмены пока элемент в очереди

### Ограничения payload
- Максимальный размер: 512 KiB
- Максимум потоков в отчёте: 10
- Максимум фреймов на поток: 50
- Максимум binary images: 20
- Максимум breadcrumbs: 50

## Backend требования

### Обязательные меры защиты
- Принимать только известную `schema_version`
- Строгий максимальный размер тела запроса
- Rate limiting (минимум 10 отчётов в час на установку)
- Минимизированные access logs (без сохранения полных payload)
- Retention policy: максимум 90 дней
- Шифрование transport (HTTPS) и storage
- Не требовать лицензионный ключ
- Отделять crash reporting от аналитики

### Symbolication
- Архивировать dSYM для каждой сборки
- Привязка dSYM к build number и binary UUID
- Автоматическая symbolication на backend
- Проверка соответствия UUID отчёта и dSYM

### Защита от злоупотреблений
- Валидация app/build metadata
- Per-install rate limit
- Server-side deduplication по fingerprint crash
- Monitoring аномальной активности

## Privacy гарантии

### IP-адрес
IP-адрес технически виден серверу на транспортном уровне. Политика backend:
- Не сохранять IP в персистентное хранилище
- Использовать только для rate limiting
- Удалять из access logs через 24 часа

### Аналитика
Crash reporting полностью отделён от аналитики:
- Нет отслеживания пользовательского поведения
- Нет сессий или воронок
- Нет интеграции с рекламными платформами

### Third-party SDK
Не используются сторонние crash reporting SDK. Решение полностью собственное для контроля над данными.

## Обновление политики

При изменениях в политике:
1. Обновить этот документ
2. Обновить `docs/privacy.html`
3. Обновить текст в настройках приложения
4. Указать дату обновления
