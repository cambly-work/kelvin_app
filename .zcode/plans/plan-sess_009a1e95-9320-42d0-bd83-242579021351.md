## План: Thermal Rules в CoolingSettingsPage (NewSettings.swift)

### Что делаем
Добавляем Thermal Rules (пороговые уведомления) в новую секцию Cooling настроек Kelvin app. В старых настройках это уже работает — мы просто переносим UI в SwiftUI.

### Изменения только в 1 файле: `Sources/NewSettings.swift`

---

### Шаг 1: Добавить `@Published` свойства в `KelvinSettingsModel` (строка ~165)

```swift
@Published var thermalLive: [AlertKind: Double] = [:]  // live sensor values
private var thermalTimer: Timer?
```

Добавить методы:
- `startThermalPolling()` — запускает Timer (каждые 2.5 сек) для чтения CPU/GPU temp через `SMCReader` и CPU load через `SystemUsage.shared.cpu()`, battery через `BatteryReader`
- `stopThermalPolling()` — инвалидирует и nilит timer
- Вызывать `startThermalPolling()` при появлении CoolingSettingsPage (onAppear) и `stopThermalPolling()` при исчезновении (onDisappear)

### Шаг 2: Расширить `CoolingSettingsPage` (строка ~518)

Добавить вторую `KelvinCard` после существующей карточки "Профиль вентиляторов" — "Тепловые правила".

Карточка содержит 5 правил (`AlertKind.allCases`), каждое правило отображается как:

**a) Строка заголовка правила** — `SettingsRow` без control:
- SF Symbol (thermometer.medium для temp, battery.25% для battery, cpu для cpuLoad)
- Название правила (`AlertKind.label`)
- Detail: текущее live-значение `"сейчас 72°"` / `"сейчас 45%"` (из `model.thermalLive[kind]`)

**b) Тоггл правила** — `SettingsRow` с Toggle:
- `"Уведомить при срабатывании"`
- Toggle binding читает/пишет `SettingsStore.alertRules[index].on`
- При включении: `AlertsEngine.shared.primeAuthorization()`
- При выключении: `AlertsEngine.shared.onRulesChanged()`
- Disabled если мастер-уведомления выключены

**c) Слайдер порога** (только если правило включено И мастер включен):
- `SettingsRow` с `Slider` внутри `HStack` с `Text("\(threshold, specifier: "%.0f")\(kind.unit)")`
- Range из `kind.range` (lo/hi/step)
- Binding через `SettingsStore.alertRules[index].threshold`
- `Slider(value:, in: lo...hi, step: step)`

**d) Тоггл "Boost fans to max"** (только для `kind.canBoostFans`, Pro-gated):
- `SettingsRow` с Toggle
- `requirePro(.fans)` gating через `SettingsWindowController.shared`
- Binding: `rule.action = on ? .fansMax : nil`

**e) CardDivider** между каждым правилом

**f) Info-текст внизу** карточки (опционально): краткое описание логики гистерезиса

### Шаг 3: Уведомление об изменениях

При любом изменении правила (тоггл, порог, action):
- Обновить `SettingsStore.alertRules` (запись в UserDefaults)
- Вызвать `AlertsEngine.shared.onRulesChanged()` для пересчёта активных boosts
- `model.changed()` для пересчёта revision

### Как читаем правила (helper)

Добавить helper-функцию в NewSettings.swift:
```swift
private func alertRules() -> [AlertRule] { SettingsStore.alertRules }
private func updateAlertRule(_ kind: AlertKind, _ transform: (inout AlertRule) -> Void) {
    var rules = SettingsStore.alertRules
    if let idx = rules.firstIndex(where: { $0.kind == kind }) {
        transform(&rules[idx])
        SettingsStore.alertRules = rules
    }
}
```

### Что НЕ трогаем
- `AlertsEngine` — не меняем, он уже работает
- `SettingsStore.alertRules` getter/setter — не меняем
- Старые настройки (`Settings.swift`) — не меняем
- `SettingsKit.swift` — не используем (это AppKit)
- `NotificationSettingsPage` — мастер-тоггл уведомлений уже там, не дублируем

### Безопасность
- Все данные через `SettingsStore` — совместимы со старыми настройками
- `AlertsEngine.shared.primeAuthorization()` и `.onRulesChanged()` — те же вызовы, что и в старом UI
- Pro-gating через тот же `SettingsWindowController.shared.requirePro(.fans)`
- Timer для live values останавливается когда страница не видна (onDisappear)
